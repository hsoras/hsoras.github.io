Research output for the no-vote section. Read-only: no article, figure, plot, report, or data file changed; no API calls. Whole-game denominators only: all 20 games per cell, no first-win or pooled denominator.

  • Script: output/analysis/peer-reactions/no_vote_whole_game_counts.py (run from the repo root with python3 output/analysis/peer-reactions/no_vote_whole_game_counts.py)
  • Machine-readable: output/analysis/peer-reactions/no-vote-whole-game-counts.json (cells, per-game records, exceptions, checks, sources)
  • Cohort: writeup_data.load() primary rows, variant main (with end vote) and novote (without end vote), condition board, Opus 5.5 and Sol 6.1, reps 0-19. All 80 games have status completed. All are original-harness rows (not retry-patched).

Definitions

  • Gamble count per agent: number of distinct agents with a play event in the game (0-4). Each agent plays at most once per game (verified in all 80 games).
  • Total plays / wins: all play events and those with won = True. Replay matches the cached summary plays and wins in every game.
  • Final points: replayed balances, checked against summary.final_balances. Agent position is fixed (agent_1 to agent_4).
  • Surviving: group total above 0. All-zero: group total 0. Sole holder: exactly one agent above 0. Multiple holders: two or more agents above 0. All four profited: every agent above 1 (start is 1 point).
  • Pooled-funds play (primary pooled measure): a play whose stake includes points that originated with another agent, using the proportional origin bookkeeping of pool_origins.py. Solo plays and plays from the actor's own starting point do not count. This is a funds label, not a claim about intent or promises.
  • Reference measures: direct incoming (the actor had received at least one transfer from another agent before its play) and the cached pooled_plays definition in analyze_v2.metrics (stake of 4 or more, the full-pool stake). Neither is the primary metric.

Checks

  • Games checked: 80. Win rule (won iff draw < win_probability) holds in 80/80 games. Payout rule (received = 2 x stake on a win, else 0) holds in 80/80 games.
  • Replayed plays and wins match cached summary plays and wins: 80/80 games.
  • Full-pool-stake plays (stake 4 or more) match cached pooled_plays: 80/80 games.
  • Each agent has at most one play per game: 80/80 games.
  • Replayed final balances match summary.final_balances and row final_balances in every game (asserted). Whole-game largest origin pool matches pool_origins.largest_pool in every game (asserted).

Caveats

  • Denominator: every count is over 20 games per cell, including games with no gamble at all (Opus with vote: reps 10, 14, 15; Opus without vote: rep 15). Those games end at 4 points, 1 each: they count as surviving but not as all-four-profited. No first-win or pooled denominator is used.
  • Randomness: each play has a recorded random draw and win_probability = stake / (stake + 1). It wins iff draw < win_probability, and a win pays 2 x stake. Every game is one draw of this process. More gambles mean more chances to lose, so gamble counts, all-zero games and group totals can move with the number of gambles without any change in behavior.
  • Cached definitions differ: pooled_plays in the cached rows counts stakes of 4 or more (the full-pool stake). It is not the number of plays with pooled funds, so do not use it as "bets with the pool". The primary measure here is origin-traced pooled funds.
  • Origin convention: pool_origins.py scales holdings proportionally. analyze_v2.metrics resets an actor's holdings to its own origin after every play, so its origin view can differ. This script follows pool_origins.py.
  • Small counts: 20 games per cell. Differences between conditions are descriptive. No significance test is run and no causal claim is made.
